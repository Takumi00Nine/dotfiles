# cmux-next-watch

cmux Dock の「Project」枠に、供給側（ai-env の `cmux-next-model.sh`）から
受け取った1ティック分のフレームを描くだけの常駐スクリプト。v3
（cmux-session-todo 設計 §28〜§31）で Vault・外部脳ログの解析はすべて
供給側へ移り、この常駐は**表示専用**（Vault にも `~/.claude/logs/` にも
cmux にも一切触れない）になった。

同じ `cmux/` 配下の共有 lib（`lib-dock-view.sh`・`lib-supply-frame.sh`）に
依存する。実体のディレクトリ（`~/work/dotfiles/cmux/`）が壊れていて lib が
見つからないときは、理由を1行出して終了コード1で止まる（機能を欠いたまま
無言では起動しない）。

## 表示例

```
▶ 稼働中 (2)
5 svwb-pilot 実データ照合を回す
6 takumi009- (next未設定)

⏸ 待ち (1)
7 p-wait 返事待ち 9/25 10:00

⏸ 保留 (1)
8 avatar-swi 配布方式のたたき台を書く

外部脳 OK 候補390件
```

Dock 契約は `cmux-dock-frame/4`（cmux-session-todo 設計 v5 §40.4）。区分は
`稼働中`／`待ち`／`保留` の 3 値で、`待ち` は供給側が Vault ノートの
`wait_until: YYYY-MM-DDTHH:MM`（`YYYY-MM-DD` 可＝その日の 00:00）と判定
時刻を比べて分類したもの（分類は供給側だけ。この常駐は時刻を読まず、区分
と待ち日時を供給側の値のまま描く）。待ちのエントリ行は末尾に待ち日時の
短縮形 `M/D HH:MM`（固定の文字列変換）を付ける。**待ちが 0 件のときは待ち
ブロック（見出し・空行）ごと出さない。**

外部脳ヘルス行は health-self-explain 設計 v1.2 §6・D-3＝本人向け 1 行
3 値（`OK`／`WARNING`／`ERROR`）＋末尾付記のみ。旧契約
（`cmux-dock-frame/1`）の見出し行（`⚠ 外部脳`／`✅ 外部脳`）・種別2種
（`棚卸し`／`週次`）・`warn`／`ok` の2値は廃止。

供給側が使えない・応答しない・契約の版が合わないときは、理由行1行だけを
出す（`AI環境 未導入`／`AI環境 応答なし`／`AI環境 版ちがい`）。

## 表示規則（稼働中・保留はv1・v2から不変／外部脳ヘルス行はv3・待ちブロックと高さの決め方はv5で変更）

- 稼働中・待ち・保留の3セクションに分け（この順）、各見出しの件数は
  **供給側の対応表の全件数**（クランプで行が落ちても件数は変わらない）。
  待ち 0 件のときは待ちセクションを出さない。
- 番号は**供給側が採番した値をそのまま描く**（この常駐は連番を振り直さ
  ない＝FR-63）。
- 正式プロジェクト名は先頭10コードポイントに切り詰め（省略記号無し）。
  `next` 値は端末幅にコードポイント単位で切り詰め、超過時は末尾に `…`
  を付ける。`next` 値が空のノートは dim色で `(next未設定)` と表示する。
  待ちの行は番号・名前・短縮形を全部残し、`next` 欄だけを切り詰める
  （`3 p-wait 返… 9/25 10:00`）。
- 高さ超過（クランプ）のときは表示中のセクションの見出し（待ちありなら
  3 つ・待ち 0 件なら 2 つ）・`…他N行`（末尾に 1 行）・外部脳行を残し、
  残せるエントリ行数を**表示中のブロック（待ちありなら 3・待ち 0 件なら 2）**
  へ均等配分（床）→余りを稼働中→待ち→保留の順に 1 行ずつ→件数不足の
  ブロックの余剰を同じ順で回す（各ブロック内は先頭から・番号は通し番号の
  まま飛び番で可）。高さは
  `CMUX_NEXT_ROWS`（明示指定）＞ `stty size`（端末取得）＞ 既定 4 行の順で
  決まり、常駐の書き出しは末尾 LF なし（h 行を h−1 個の LF で書く＝最下行
  の LF でのスクロールにより先頭行が隠れない＝FR-101）。
- 外部脳ヘルス行は、B行が0行のフレームでは出さない（判定機が動かない
  ときの縮退＝health-self-explain 要件 FR-15 の例外・設計 v1.2 §14-7）。
  B行は高々1行（種別は常に`外部脳`）で、
  見出しは付けず `<種別> <本文>` をそのまま描く。色は3値対応＝
  `ok`緑・`warn`オレンジ・`error`赤（`38;5;203`・本人裁定 OQ-1）。

## 使い方

```
cmux-next-watch.sh [--once]
```

`--once` は1フレームを出して終了する（テスト・動作確認用）。それ以外の
引数（未知の引数・`--list`）は使い方を出して終了コード非0で即座に終わる。
`--list`（番号・正式プロジェクト名・`next` 値・区分・待ち日時の5列 TSV）は供給側
（`~/work/takumi009-ai-env/cmux/cmux-next-model.sh --list`）へ移設済み
で、この常駐は提供しない。

## 環境変数

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `CMUX_DOCK_SUPPLY_PROJECT` | `$HOME/work/takumi009-ai-env/cmux/cmux-next-model.sh` | 供給側の呼び出し口（テスト・実験用の上書き口） |
| `CMUX_DOCK_SUPPLY_TIMEOUT` | 5 | 供給側の呼び出しの締切（秒）。1〜60の整数以外は既定へ戻す |
| `CMUX_NEXT_INTERVAL` | 60 | 常駐ループの周期（秒） |
| `CMUX_NEXT_REDRAW_HEARTBEAT` | 600 | 同一フレームでも強制再描画する間隔（秒） |
| `CMUX_NEXT_ROWS` | 未設定（`stty` 実測・取得不能なら 4） | 端末の高さの強制上書き（正整数のときだけ有効＝高さの明示指定口・FR-101 ①） |
| `CMUX_NEXT_COLS` | 未設定（`stty` 実測） | 端末の桁数の強制上書き（正整数のときだけ有効。テスト・実験用） |
| `CMUX_DOCK_MAX_COLS` | 60 | 桁数の実測値（`stty` 実測）がこの値を超えるとき丸める上限。Dock ペインの pty 桁数が可視幅より大きく報告される既知の癖への対処（`lib-dock-view.sh` の `term_cols()` 共通・Task 常駐と共有） |

## 供給側との契約

呼び出しは1ティックにつき1回、`$CMUX_DOCK_SUPPLY_PROJECT --frame` を実行
し、TSV 形式の1フレーム分を受け取る（契約の詳細は cmux-session-todo 設計
§29）。締切・大きさ上限（65536バイト・1000行）に達したときは供給側を
プロセスグループごと終了させ、`AI環境 応答なし` へ縮退する。
